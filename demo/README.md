# Skout Scan: review a gap, add an eval, observe resolution

Your agent has evals. But are they testing the behaviors that matter?

This demo uses the existing [Pydantic AI refund assistant](../examples/pydantic-ai-agent/).
Its validator raises `ModelRetry` for refunds above 500. Existing tool tests and
Pydantic Evals evidence do not verify that failure path. Enable the supplied
pytest eval, rescan the same workspace, and Skout records observed resolution.
All agent and eval files are read statically; none are imported or executed.

## Prerequisites

Use Python 3.12+ and an installed Skout package supporting Pydantic AI
(version 0.1.6 is declared in this checkout). No editable install or example
framework dependencies are needed. From a fresh clone:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install skout-scan==0.1.6
skout --version
```

To use a local wheel instead, replace the install command with:

```sh
python -m pip install dist/skout_scan-0.1.6-py3-none-any.whl
```

If a wheel has not been built, `python -m pip install build` followed by
`python -m build --wheel` creates it. Installation/building may need network
access; the demo itself needs no network, credentials, or API key. Check the
installed version before recording: package metadata can lag a source checkout.

## Run manually

Start in the Skout repository root with `skout` on PATH. Keep these variables in
the same shell:

```sh
DEMO_SCRIPTS="$PWD/demo/scripts"
DEMO_ROOT=$(sh "$DEMO_SCRIPTS/prepare_demo.sh")
cd "$DEMO_ROOT"
ls agent.py evals.py tests/test_tools.py
skout doctor
skout scan . --no-progress
skout findings
skout review
# At the Classification prompt, type add_eval and press Enter.
skout findings
```

Preparation copies an explicit file allowlist into a fresh `/tmp/skout-demo.*`
directory. It leaves the source example untouched and excludes environments,
state, caches, generated output, and active solution tests. `doctor` readiness
means the repository is assessable, not that the agent has adequate coverage.

Verified initial output: four behaviors, two eval scenarios, two candidate
pairs, and one open finding for `validate_refund` failure behavior in `agent.py`.
`skout findings` shows the actual `raise ModelRetry(...)`, missing verification,
and suggested scenario. Finding IDs are generated by Skout, never supplied by
these scripts. The ID remains visible below the possibly truncated table.

The real review prompt accepts `add_eval` followed by Enter. This persists an
intention: the finding remains open and the test is still absent. Skout does not
generate or execute a test.

Enable the original solution and rescan **without resetting**:

```sh
sh "$DEMO_SCRIPTS/enable_solution.sh" "$DEMO_ROOT"
cat tests/test_retry.py
skout scan . --no-progress
skout findings
```

The copied test uses refund amount 900 and `pytest.raises(ModelRetry)` around
`validate_refund`. Activation preserves the solution byte for byte and is safe
to rerun. It refuses to overwrite changed files.

Verified second output: three eval scenarios, four candidate pairs, one resolved
finding and zero open findings. `skout findings` reports the same ID with
`resolved`, `covered`, and `Observed resolution: yes`. Confirmed impact stays
`no`: this recording demonstrates observed test resolution only. Historical
title/explanation text still describes the original gap; status and observed
resolution fields show its current lifecycle.

## Reset for a fresh demonstration

Only after finishing the complete before/after sequence:

```sh
sh "$DEMO_SCRIPTS/reset_demo.sh" "$DEMO_ROOT"
```

Reset removes only the unchanged activated solution and `.agentguard/` inside
a marker-validated, demo-owned temporary workspace. It refuses source example
paths, missing ownership markers, linked paths, and changed solution files.
Other workspace files remain. Repeating reset is safe. Run the initial commands
again, or return to the checkout and prepare another fresh workspace.

Never reset or delete state between the first and second scan: that would
discard the lifecycle evidence this demo is intended to prove. Temporary copies
are outside Git; no scan state or copied repositories belong in commits.

## Record with VHS

Install [VHS](https://github.com/charmbracelet/vhs#installation) separately if
needed. Its recording dependencies are `ttyd` and `ffmpeg`. On macOS/Homebrew:

```sh
brew install vhs ttyd ffmpeg
```

From the repository root, with your Skout environment activated:

```sh
vhs demo/skout-demo.tape
```

The tape prepares its own fresh workspace, executes real CLI commands, enables
the supplied solution, and preserves state across both scans. It uses a neutral
prompt and `/tmp` path, with pauses on genuine finding output. Installation
output is outside the recording. Shell comments provide captions, not simulated
CLI results. The tape displays a genuine `doctor` excerpt using `grep -A 3`, highlighting
frameworks, evals, behaviors, and readiness without scrolling through exclusions.

Target length is 60–90 seconds including typing. See [storyboard](storyboard.md)
and [narration/LinkedIn copy](narration.md). Regenerate the GIF with the same VHS
command after changing pacing. An optional MP4 output line is provided in the
tape; uncomment it for outreach, keeping large intermediates untracked.

Before using media publicly, inspect the entire animation and confirm the
uncovered source, solution, same finding ID, and observed resolution are readable.
Check duration, dimensions, and size:

```sh
ffprobe -v error -show_entries format=duration,size -show_entries stream=width,height -of json demo/assets/skout-demo.gif
```

See [asset notes](assets/README.md) for media status. The root README must embed
only a successfully rendered and verified GIF, using a relative repository link.

## Captioned video exports

The original MP4 and silent GitHub GIF are preserved. Enhanced exports add a
160-pixel caption band below the original terminal content: **1440×1160**,
**75.28 seconds**, H.264/yuv420p at the source's 25 fps. Captions never overlap
frameworks, finding IDs, commands, or resolution output.

- [Captioned-only MP4](assets/skout-demo-captioned.mp4): captions, no music.
- [Final MP4](assets/skout-demo-final.mp4): captions plus subtle background music.

Use the final MP4 for LinkedIn and SkoutHQ.com; use the captioned-only version
where a silent presentation is preferable. MP4 exports remain ignored by Git;
these links work in the local checkout after building. Upload the final export
to your chosen video/site hosting separately before linking it publicly. The
root GitHub GIF remains silent because GIF does not carry an audio track.

Edit [skout-demo.srt](captions/skout-demo.srt) to change caption wording/timing.
Use at most two lines per cue, in chronological order and inside the video
runtime. The build generates [skout-demo.ass](captions/skout-demo.ass) from it;
ASS is derived, so edits to it are replaced. Styling lives in
`scripts/enhance_video.py`: warm-white Arial at 38 px, translucent dark boxes,
centered inside the added caption band. No animated text is used.

From the repository root:

```sh
sh demo/scripts/build_enhanced_video.sh
```

Requirements: Python 3 (standard library only), FFmpeg with libass subtitles
support, and ffprobe. Some minimal FFmpeg builds lack that filter. On macOS,
install `ffmpeg-full` with Homebrew if needed. The build detects its standard
Apple Silicon Homebrew location without changing your shell configuration.
For another installation, specify the executables explicitly:

```sh
FFMPEG="/path with spaces/ffmpeg" FFPROBE="/path with spaces/ffprobe" sh demo/scripts/build_enhanced_video.sh
```

Supply the existing licensed music as `demo/assets/music/background.mp3` with
[provenance notes](assets/music/README.md). The user-supplied Pixabay download is
preserved and copied locally to that path. Both raw music copies are ignored.
The build never downloads or substitutes music. If music or provenance notes
are missing, the captioned export is still generated and the music version is
reported as pending. An older final export is explicitly reported as stale.

Music starts at **18% amplitude** (about −14.9 dB relative to the source), fades
in over 2 seconds, and fades out over the final 5 seconds. It is trimmed, never
looped, and encoded as AAC. Existing original audio, if present, is mixed with
the background; the current original has none. The limiter does not boost the
music. For later narration, lower/duck the music in the build's audio filter.

The build validates cue ranges, dimensions, codec, duration and full decoding
before replacing each derived output. It uses temporary intermediates and never
writes to the original recording. Run it again after caption edits to regenerate
both exports. Verify metadata with:

```sh
ffprobe -v error -show_entries format=duration,size:stream=codec_name,codec_type,width,height,r_frame_rate -of json demo/assets/skout-demo-final.mp4
```

Inspect the captioned frames at 5, 15, 25, 35, 45, 55 and 70 seconds, and listen
to the final track at your intended playback volume before public use. Automated
peak/fade measurements complement, but cannot replace, a human listening check.

## V2 master: full review-to-resolution workflow

V2 preserves all v1 assets and does not replace the root README GIF. From the
checkout root, with the installed `skout` and its Python environment on PATH:

```sh
vhs demo/skout-demo-v2.tape
sh demo/scripts/build_demo_v2.sh
```

VHS records a real interactive terminal: `skout review`, type `add_eval`, Enter.
It does not write classification directly to SQLite. Both scans use the same
fresh temporary copy and database. `head`, `grep`, and `sed` select genuine CLI
excerpts; they do not substitute output. The recording has a 32 px terminal font
versus v1's 24 px. The new test is the existing byte-preserved solution.

Final scene command, from the prepared workspace:

```sh
python "$DEMO_SCRIPTS/show_resolution.py"
```

This is a **demo helper, not a Skout CLI subcommand**. It reads the persisted
finding, verifies resolved/covered/add_eval, and joins stored matched eval IDs
to statically extracted eval source paths. It refuses to report success unless
`tests/test_retry.py` is among those matches. No target code is imported.

Editable timing sources:

- `captions/skout-demo-v2.srt`: narration captions; ASS is generated alongside it.
- `annotations/v2.json`: time windows and pixel rectangles in the 1440×1000
  terminal coordinate system. A separate 160 px caption band is added below.
- `skout-demo-v2.tape`: real command sequence and pauses.

Annotations must be rechecked against extracted frames after any tape/font or
terminal-size change. The build checks dimensions, duration, cue overlap and
annotation bounds, then fully decodes both exports. It preserves source fps.

Outputs (generated locally, ignored by Git):

- `assets/skout-demo-v2-terminal.mp4`: raw terminal master.
- `assets/skout-demo-v2-silent.mp4`: captions and transient annotations.
- `assets/skout-demo-v2.mp4`: same video with the new soundtrack when available.

FFmpeg requires libass. On macOS the existing keg-only `ffmpeg-full` is selected
automatically; elsewhere set `FFMPEG` to a suitable executable. Existing v1
`build_enhanced_video.sh` still rebuilds only the preserved v1 outputs.

Music provenance, candidate comparison and retrieval instructions are in
[UPBEAT-LICENSE.md](assets/music/UPBEAT-LICENSE.md). Raw music remains untracked.
The v2 build uses only `skout-upbeat.mp3`, never the old ambient track. Without
that file, both v2 exports are silent and the build clearly reports music pending.
Human listening and phone playback review are still required before publication.
No short LinkedIn edit is generated.

V2 annotation windows: uncovered 18–21s; typed add_eval 34–36.5s;
new test verification 49–52s; resolved/covered 74–78s. All are thin 2 px
outlines positioned using real frames. Captions occupy their own band and
include explicit intent-versus-test-versus-resolution language. The terminal
is intended for laptop playback or landscape/fullscreen on a phone; portrait
inline playback cannot make a full terminal equally readable.
